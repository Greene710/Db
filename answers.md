# Разбор практической работы ShopDB

## Задача 1. ТОП-5 клиентов за последние 30 дней

Используются таблицы `Customers` и `Orders`.

- `INNER JOIN` соединяет клиента с его заказами.
- `WHERE` оставляет заказы за последние 30 дней, включая текущую дату.
- `SUM(o.TotalAmount)` суммирует покупки клиента.
- `GROUP BY` объединяет заказы одного клиента.
- `ORDER BY ... DESC` сортирует от большей суммы к меньшей.
- `LIMIT 5` оставляет первые пять строк.

## Задача 2. Клиенты и средний чек по городам

- `COUNT(DISTINCT c.CustomerID)` считает уникальных клиентов в городе.
- `AVG(o.TotalAmount)` вычисляет среднюю сумму заказа.
- `GROUP BY c.City` группирует результат по городам.
- `HAVING AVG(o.TotalAmount) > 5000` оставляет города, где средний чек строго больше 5000.
- `ORDER BY c.City DESC` сортирует названия городов по убыванию.

## Задача 3. Продажи по категориям

- Таблицы `Categories`, `Products` и `OrderDetails` соединяются через `JOIN`.
- `SUM(od.Quantity)` считает проданные единицы.
- `SUM(od.Quantity * p.Price)` считает выручку.
- Используется именно `Products.Price`, как указано в условии, а не `OrderDetails.Price`.
- `GROUP BY` группирует результат по категориям.

## Задача 4. Клиенты без заказов

### Вариант 1: NOT IN

Внутренний запрос получает идентификаторы клиентов из таблицы заказов. Внешний запрос выбирает клиентов, чьего идентификатора нет в этом списке.

### Вариант 2: LEFT JOIN

`LEFT JOIN` сохраняет всех клиентов из левой таблицы. Если заказ не найден, поля таблицы `Orders` будут равны `NULL`. Условие `WHERE o.OrderID IS NULL` оставляет только клиентов без заказов.

## Вопросы для защиты

**1. Чем отличается WHERE от HAVING?**  
WHERE фильтрует строки до группировки, HAVING фильтрует группы после GROUP BY.

**2. Чем отличается INNER JOIN от LEFT JOIN?**  
INNER JOIN возвращает только строки с совпадениями в обеих таблицах. LEFT JOIN сохраняет все строки левой таблицы, даже если справа совпадения нет.

**3. Для чего нужен GROUP BY?**  
Для объединения строк с одинаковыми значениями в указанных столбцах, например для подсчёта продаж по городам.

**4. Что такое PRIMARY KEY?**  
Первичный ключ — поле или набор полей, однозначно определяющих запись в таблице.

**5. Что такое FOREIGN KEY?**  
Внешний ключ — ограничение, связывающее записи одной таблицы с записями другой и обеспечивающее ссылочную целостность.

**6. Чем отличается NOT IN от LEFT JOIN?**  
NOT IN проверяет, что значение отсутствует в результате подзапроса. LEFT JOIN присоединяет связанную таблицу и позволяет найти строки без совпадения через IS NULL.

**7. Для чего нужна SUM()?**  
SUM() вычисляет сумму значений столбца или выражения.

## Примечания

- Запросы написаны для MySQL 8.0+.
- В задаче 2 средний чек считается как средняя сумма заказа, а количество клиентов — как число уникальных клиентов с заказами в городе.
- В задаче 3 выручка рассчитывается по текущей цене товара из `Products.Price`, а не по сохранённой цене из деталей заказа.
